# rrpf（hosp.jp 原稿の作業場所）

Horizon-Shift Partners の公式サイト [hosp.jp](https://hosp.jp) に載せる文章を、
公開前に書いて、見直して、ためておくための場所です。

## これは何のためのものか

- ブログ記事、テーマ別ポータルの原稿、提案書や講演資料のたたき台を、ここで下書きします。
- 下書きは「いつ、誰が、どこを直したか」がすべて記録に残ります。前の版に戻すこともできます。
- サイト本体（WordPress）とは別物です。ここに置いただけではサイトには何も反映されません。
  公開するときは、仕上がった原稿を人の手で WordPress に貼り付けます。

## 使い方（ふだんの流れ）

1. **頼む**: Claude に「〇〇ポータル向けに△△の記事を書いて」のように依頼します。
2. **下書きが届く**: Claude が原稿を書き、「プルリクエスト」という形で提出します。
   プルリクエストは「この原稿を加えてよいですか」という確認依頼のことです。
   GitHub の画面で、追加・変更された文章をそのまま読めます。
3. **確認する**: 内容を読み、直してほしい点があればコメントで伝えます。Claude が修正します。
4. **確定する**: 問題なければ「マージ」ボタンを押します。これで原稿が正式に保管されます。
5. **公開する**: 確定した原稿を WordPress に貼り付けて公開します。

確定前の下書きは正式な保管場所（`main`）には入らないので、途中の文章が混ざる心配はありません。

## 中身の構成

| 場所 | 入るもの |
| --- | --- |
| `README.md` | このファイル。リポジトリの説明 |
| `CLAUDE.md` | Claude が作業するときの前提と書き方のルール |
| `posts/` | ブログ記事 |
| `portals/<ポータル名>/` | テーマ別ポータルの原稿（例: `portals/ppp/` は公民連携ポータル） |
| `materials/` | 提案書・講演資料のたたき台 |

フォルダは、最初の原稿ができたときに作ります。
原稿のファイル名は `2026-10-22-short-title.md` のように「日付＋短い英数字のタイトル」にします。

ポータル名はサイトの URL の末尾と同じです。

| ポータル名 | ポータル |
| --- | --- |
| `ppp` | 公民連携ポータル |
| `gov-ai` | 自治体生成AIポータル |
| `fm` | 公共施設マネジメント |
| `energy` | 自治体エネルギーポータル |
| `hr` | 自治体人材ポータル |
| `gov-biz` | 自治体ビジネス参入 |
| `chiiki-mirai` | 地域未来交付金 |
| `kotsu` | 地域公共交通 |
| `biz-ai` | 企業の生成AI導入 |
| `edu-ai` | 学校と教育の生成AI |
| `const-ai` | 建設AI導入 |
| `ai-security` | AIセキュリティ |

## 原稿の約束事（抜粋）

- 文体は「です・ます」調です。
- 数値や制度の説明には、必ず出典を原稿の最後に書きます。確かめられない数値は書きません。
- クライアント名や非公開の案件情報は、了承なしに公開用の原稿へ書きません。

詳しいルールは [CLAUDE.md](CLAUDE.md) にまとめています。
